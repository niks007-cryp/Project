## 2. Technical Distinction: Route 404 vs DEPLOYMENT_NOT_FOUND

| Error Type | Meaning | Vercel Edge Behavior |
|------------|---------|----------------------|
| `404: NOT_FOUND` | Deployment exists, but missing route/file | Edge router finds deployment, but static path `/` doesn't match a file |
| `DEPLOYMENT_NOT_FOUND` | Domain/Alias is unassigned or deployment ID missing | Edge router cannot locate any deployment record associated with requested domain |

## 3. Root Cause Analysis
The domain `https://project-niks007-cryp.vercel.app` is currently unassigned in Vercel's global edge routing table.

When a repository named `Project` is linked to Vercel, Vercel creates deployment URLs under the account slug, such as:
- `https://project-<team-slug>.vercel.app`
- `https://project-git-main-<team-slug>.vercel.app`

Because `project-niks007-cryp.vercel.app` was manually constructed rather than queried from the active Vercel project dashboard, Vercel's edge network returned `DEPLOYMENT_NOT_FOUND`.
